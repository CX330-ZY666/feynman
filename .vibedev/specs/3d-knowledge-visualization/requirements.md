# 3D 知识图谱可视化需求文档

## 功能概述
基于 Three.js 构建交互式 3D 知识图谱可视化系统，为用户提供全新的三维知识探索体验。系统分三个阶段实现：基础 3D 场景演示、3D 知识图谱渲染、高级交互功能。

---

## 用户故事与验收标准

### 1. 基础 3D 场景演示
**用户故事：** 作为一名学习者，我想看到一个简单的 3D 旋转立方体演示，以便理解 Three.js 的基本工作原理。

**验收标准：**
1.1 WHEN 用户访问 `/3d-world` 路由时，系统应渲染一个全屏的 3D 场景容器（高度至少 80vh）

1.2 WHEN 3D 场景初始化完成时，系统应在场景中心显示一个绿色立方体（尺寸 1x1x1）

1.3 WHILE 3D 场景处于活动状态时，立方体应持续自动旋转（x 轴和 y 轴每帧增加 0.01 弧度）

1.4 WHEN 用户移动鼠标左键拖拽时，系统应允许用户旋转视角

1.5 WHEN 用户滚动鼠标滚轮时，系统应允许用户缩放视野

1.6 WHEN 用户移动鼠标右键拖拽时，系统应允许用户平移场景

1.7 WHEN 用户调整浏览器窗口大小时，系统应自动调整 3D 场景的尺寸和相机宽高比

---

### 2. 导航集成
**用户故事：** 作为一名用户，我想从导航栏快速访问 3D 场景页面，以便方便地切换不同的可视化视图。

**验收标准：**
2.1 WHEN 用户已登录时，导航栏应显示"3D 视界"链接

2.2 WHEN 用户点击"3D 视界"链接时，系统应导航到 `/3d-world` 页面

2.3 WHERE 新的 3D 页面应与现有的 2D 知识图谱页面（`/graph`）独立存在

---

### 3. 3D 知识图谱渲染
**用户故事：** 作为一名知识管理者，我想在 3D 空间中查看我的知识图谱，以便从全新的维度理解知识之间的关联关系。

**验收标准：**
3.1 WHEN 页面加载时，系统应从 API `/api/graph/knowledge-map` 获取图谱数据（nodes 和 edges）

3.2 WHERE 每个知识点节点应被渲染为一个 3D 球体（半径 0.2，使用 SphereGeometry）

3.3 WHILE 渲染节点时，每个球体应使用 MeshStandardMaterial 材质，颜色随机生成

3.4 WHEN 节点创建时，系统应将节点随机放置在空间中（x, y, z 范围：-5 到 5）

3.5 WHERE 节点之间的关系（边）应被渲染为连接两个球体的直线

3.6 WHILE 渲染边时，线条应使用灰色（0xaaaaaa），透明度 0.5

3.7 WHEN 所有节点和边渲染完成时，系统应在节点的 userData 中存储原始数据（id, label）

3.8 WHEN 用户每次刷新页面时，节点位置应重新随机生成

---

### 4. 3D 光照系统
**用户故事：** 作为一名用户，我想在 3D 场景中看到有真实光照效果的知识星球，以便获得更沉浸式的视觉体验。

**验收标准：**
4.1 WHEN 3D 场景初始化时，系统应添加环境光（AmbientLight，颜色 0xffffff，强度 0.5）

4.2 WHEN 3D 场景初始化时，系统应添加点光源（PointLight，颜色 0xffffff，强度 1，位置 (5,5,5)）

4.3 WHERE 场景背景色应设置为深色（如 0x1a2a3a）以突出光照效果

---

### 5. 鼠标悬停高亮交互
**用户故事：** 作为一名用户，我想在鼠标悬停在知识星球上时看到高亮效果，以便快速识别当前关注的节点及其关联关系。

**验收标准：**
5.1 WHEN 用户移动鼠标时，系统应实时检测鼠标射线与场景中球体的相交情况（使用 Raycaster）

5.2 WHEN 鼠标射线与某个球体相交时，该球体的材质应变为高亮状态（emissive 属性设置为红色 0xff0000）

5.3 WHILE 鼠标悬停在球体上时，与该球体相连的所有边应变为高亮状态（颜色变亮或宽度增加）

5.4 WHEN 鼠标移开球体时，球体和边应恢复到原始状态

5.5 WHERE 鼠标坐标应被正确转换为归一化设备坐标（NDC，范围 -1 到 1）

5.6 WHEN 有多个物体相交时，系统应只高亮最近的物体

---

### 6. 性能与资源管理
**用户故事：** 作为一名用户，我想系统能够正确管理 3D 资源，以便避免内存泄漏和性能问题。

**验收标准：**
6.1 WHEN 组件卸载时，系统应移除渲染器 DOM 元素

6.2 WHEN 组件卸载时，系统应移除窗口大小变化的事件监听器

6.3 WHEN 组件卸载时，系统应停止动画循环（通过不再调用 requestAnimationFrame）

6.4 WHERE 渲染器应启用抗锯齿（antialias: true）以提升视觉质量

---

### 7. 错误处理与边界条件
**用户故事：** 作为一名用户，我想系统能够优雅地处理异常情况，以便获得稳定的使用体验。

**验收标准：**
7.1 WHEN API 请求失败时，系统应在控制台输出错误信息

7.2 WHERE 图谱数据为空（nodes.length === 0）时，系统应等待数据加载完成后再初始化 3D 场景

7.3 WHEN 依赖项未安装时，系统应提示相关错误信息

---

## 技术约束
- 使用 Three.js 库（需安装 `three` npm 包）
- 使用 React 18+ 和 React Hooks
- 使用 React Router 进行路由管理
- 使用现有的 axios 客户端进行 API 调用
- 保持与现有代码风格和架构一致

## 非功能性需求
- 动画帧率应保持在 60fps
- 场景初始化时间应小于 2 秒
- 支持至少 100 个节点的流畅渲染
- 响应式设计，适配不同屏幕尺寸
